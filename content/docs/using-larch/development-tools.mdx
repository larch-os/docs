<Callout type="warn">
  Outline only. The homepage pitches Larch as tuned for development work, but the package list doesn't back that up yet: `packages.x86_64` currently has `vim`, `nano`, and `tmux`, general CLI tools that ship with any archiso `releng`-based profile, not a curated dev toolchain. No git, no language runtimes, no build tools, no containers.
</Callout>

## What this page needs once tools are actually chosen

- Language runtimes/toolchains the project decides to ship by default (if any) versus leaving to the user.
- Whether dev tools live in the base ISO or in a separate variant (see [Roadmap](/docs/development/roadmap) on `larch-base` vs. future variants like a tools-heavy ISO).
- Container/virtualization tooling, if any (Docker, Podman, libvirt, whatever's decided).
- Editor/IDE story: is a specific editor bundled, or is this left entirely to the user beyond a terminal editor.
- How this page's picture reconciles with the homepage's "tuned for development work" claim, they need to describe the same reality.
