## The live session doesn't suspend or hibernate

This is deliberate, not missing. `/etc/systemd/logind.conf.d/do-not-suspend.conf` overrides logind directly:

```ini
[Login]
HandleSuspendKey=ignore
HandleHibernateKey=ignore
HandleLidSwitch=ignore
```

Closing the lid, hitting the suspend key, or hitting the hibernate key all do nothing in the live session. A live/demo environment suspending or hibernating mid-session (especially on lid close, which is easy to trigger by accident while carrying a laptop around) is more likely to confuse someone testing the ISO than to help them, so it's switched off at the source.

## swayidle runs, but has no idle actions configured

niri spawns `swayidle -w` at session start (see [niri](/docs/desktop-guide/niri)), but the live session ships no swayidle config file, no dimming, no screen-off, no lock-on-idle, nothing. The daemon is running and doing nothing.

<Callout type="warn">
  This is a real gap, not a documented decision. It exists because the source machine's actual swayidle setup (see below) is tuned for a specific personal hardware/hibernate schedule that shouldn't be copied verbatim into a general-purpose live session or, eventually, a fresh install. What Larch's own default idle behavior should be (timeouts, whether to lock on idle at all in the live session) hasn't been decided yet.
</Callout>

## What a real (non-live) setup looks like

For reference, once there's an installed system to configure, here's the pattern from the project's actual daily-driver machine, not yet ported anywhere in Larch:

**`~/.config/swayidle/config`:**

```
# 5 min -> dim brightness and lock
timeout 300 'brightnessctl -s set 1%; qs -c noctalia-shell ipc call lockScreen lock' resume 'brightnessctl -r'

# 10 min -> turn off displays
timeout 600 'niri msg action power-off-monitors' resume 'niri msg action power-on-monitors'

# 30 min -> suspend then hibernate
timeout 1800 'systemctl suspend-then-hibernate'

# always lock before sleeping
before-sleep 'qs -c noctalia-shell ipc call lockScreen lock'
lock 'qs -c noctalia-shell ipc call lockScreen lock'
```

Paired with two systemd settings that aren't part of the swayidle config itself:

- `/etc/systemd/sleep.conf`: `AllowSuspendThenHibernate=yes`, `HibernateDelaySec=2h`
- `/etc/systemd/logind.conf`: `HandlePowerKey=hibernate`, `HandlePowerKeyLongPress=suspend-then-hibernate`

Whether Larch's installed-system default should match this, use longer/shorter timeouts, or skip suspend-then-hibernate entirely (it needs a swap file or partition sized for hibernation, which the installer doesn't set up yet) is an open question. See [Roadmap](/docs/development/roadmap).
