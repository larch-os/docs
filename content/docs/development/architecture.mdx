## Repo layout

```
archiso/releng/   archiso profile for the ISO, forked from the official releng profile
scripts/          build-time tooling (AUR local repo)
assets/           brand assets (logo, splash source)
docs/             design notes
```

The whole distro is a fork of archiso's official `releng` profile. Customization happens through the ISO build config, the (future) installer, and post-install provisioning, not through a custom package repo.

## Config and profile structure

```
airootfs/etc/skel/          base configs, always applied
profiles/
  shell/fish/*
  shell/zsh/*
  wm-shell/noctalia/*
  wm-shell/dank/*
```

<Callout type="warn">
  The `profiles/` tree above is the design, not yet built. The installer is meant to read a user's choices (shell, desktop shell) and copy the matching profile into the new user's home during `arch-chroot`. Right now, only the `zsh` + `noctalia` path exists, baked directly into the live user's home rather than sourced from a `profiles/` tree. See [Roadmap](/docs/development/roadmap).
</Callout>

## Why the live session config doubles as the installer default

The live ISO's noctalia config is meant to be the same one copied into a freshly installed system when a user picks noctalia at install time, single source of truth, no separate "installed system" config to keep in sync by hand.

## Key decisions worth knowing

- **oh-my-zsh is a git submodule**, not vendored files (see [Shell and terminal](/docs/desktop-guide/shell-and-terminal)). Clone with `--recurse-submodules` or the build fails loudly rather than silently shipping an empty `.oh-my-zsh` directory.
- **No `/etc/skel` for oh-my-zsh.** Deliberately scoped to the `larch` live user. The installer will wire it into the installer-created user by hand later, not through skel.
- **Never rename a built ISO file.** If a VM needs to point at a new build, repoint the VM's disk XML at the real dated filename (`out/larch-<date>-x86_64.iso`) instead.
