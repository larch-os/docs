## Built

- [x] Branding: ISO metadata, boot menus (syslinux/systemd-boot/grub), splash image, `os-release`/`issue`, hostname, motd.
- [x] Package list (niri, noctalia, dev/power-user tooling, install-time extras).
- [x] Live-session config: niri/noctalia/theming replicated from a real working setup, `larch` live user with SDDM autologin into niri.
- [x] Installer: [Calamares](https://calamares.io/)-based (`larch-calamares`), not the custom TUI originally planned (see below). Encryption on by default with opt-out, a separate unencrypted `/boot` partition, GRUB with Larch's theme, zram swap, auto-launches on live boot. Real end-to-end installs confirmed working. See [Installation guide](/docs/user-guide/installation-guide).
- [x] Installed-user provisioning: the installer-created user gets the same niri/noctalia/zsh setup as the live session, with an `install-overrides/` mechanism for the few things that have to differ once Calamares itself is gone (e.g. the noctalia bar's install button).

## Not built

- [ ] `larch-dank-shell` and `larch-hyprland` variants (no repo, no packages, no screenshot yet).
- [ ] Public release/download hosting (ISOs are built locally right now).
- [ ] A `LICENSE` file.

## Why Calamares, not a custom TUI

The original plan (below, kept for history) was a custom TUI installer, in Go with `bubbletea`, rejected as too much overhead to build and maintain. Calamares turned out cheaper: it already handles partitioning, encryption, bootloader install, and user creation, and forking it (`larch-calamares`) for branding and the few Larch-specific steps (`larch-preinstall`, `larch-postinstall`) was far less work than building and maintaining all of that from scratch.

<details>
<summary>Original custom-TUI plan (superseded)</summary>

- Runs as root via `pkexec`/`sudo` for disk operations.
- Flow: welcome screen, pre-flight checks (internet, UEFI vs BIOS), disk selection and partitioning (Auto erase-disk vs Manual), system basics (hostname, timezone, locale, keyboard, user account), custom choice pages (shell: fish vs zsh, desktop shell: noctalia vs dank material shell), summary and confirm, automated install with live progress, done screen.
- Launch: a tray icon (SNI over D-Bus, likely a small Go binary using `getlantern/systray`) or a terminal command, opening a fullscreen terminal via a niri window rule matching the installer's window title, autostarted through niri's `spawn-at-startup`.

None of this shipped. The actual installer doesn't offer a shell/desktop-shell choice at all (zsh + noctalia, same as the live session), and launches via niri `spawn-at-startup` running Calamares directly, not a tray icon or terminal wrapper.

</details>
